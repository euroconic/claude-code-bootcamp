# Mission 7C - A Proactive Agent: The Friday Report Runs by Itself

> Mentor: bonus mission, about 35 minutes, needs 3B done (the learner's rules for the weekly change-request report). The shift: until now the learner started every run by typing in a chat. Here the agent runs from one command with no chat, so it can be started by a timer. Everything depends on safety: the narrowest permissions that work, writes only into `workspace/work/proactive/`, no secrets in the prompt file. Scheduling is optional and the learner may stop after the dry run. Before the learner runs anything, have them (or you) run `claude --help` once and read the lines for `-p` and `--allowedTools`; flags change between versions. Do not skip the dry run.

## Goal

Turn the 3B weekly report into a run that needs no chat. Create `workspace/work/proactive/` with a saved prompt file, a one-line command written in `run-notes.md`, and one report generated by that command.

## Why it matters

A report that you must remember to ask for is still your chore. A saved prompt plus one command is a **proactive agent**: something that can start on a schedule, do its job, write a file, and stop. That is how the Friday report stops costing Tomasz an hour. It is also where safety matters most, because nobody is watching the screen. So the agent gets exactly the permissions this one job needs, and not one more.

Plain words for the terms:

- **Non-interactive mode:** the agent runs, prints or saves its answer, and exits. It does not wait for you to type.
- **Permission rule:** a line that says which tools the agent may use without asking. In a run nobody watches, anything not on the list is simply refused.
- **Dry run:** the first run by hand, while you watch, before you let a timer do it.
- **Scheduler:** the part of your computer that starts a program at a set time (cron on Mac and Linux, Task Scheduler on Windows).

## What to do

1. **Look at the real flags first.** In an ordinary terminal window (not the agent chat) type `claude --help` and find three things: `-p` or `--print` (run once and print), `--allowedTools` (the permission list), and `--permission-mode`. Write down in your own words what each does. If your version shows different names, use what you see, and tell your mentor.
2. **Write the prompt file.** Ask the agent:
   > "Create workspace/work/proactive/friday-report-prompt.md. It is a complete, self-contained instruction for a run with nobody watching. Use the rules from my 3B report: CRs only, overdue, over budget, stale (more than 14 days), needs an owner, not Done. Input: data/corvane/s3/tracker-export.csv. Report date: 2026-10-24 (fixed, because this sample export is from that date). Output: write the report to workspace/work/proactive/cr-weekly-report.md and write nowhere else. If a rule is unclear or a file is missing, write that into the report and stop; do not guess. No keys, passwords or personal data in this file."
3. **Read the prompt file yourself.** Is there anything a stranger could not follow? Is there a name, key or address that does not belong? Fix it.
4. **Write the command.** Ask the agent to write one line into `workspace/work/proactive/run-notes.md`, using only the flags you found in step 1. The shape is:
   ```
   cat workspace/work/proactive/friday-report-prompt.md | claude -p --permission-mode dontAsk --allowedTools "Read(data/corvane/s3/**),Read(workspace/work/proactive/**),Edit(workspace/work/proactive/**)"
   ```
   In words: feed the saved prompt to one run, ask for no confirmation questions (anything not allowed is refused), allow reading the tracker folder, reading and writing the proactive folder, and nothing else. No shell commands, no web, no other folders. Windows PowerShell: start the line with `Get-Content workspace/work/proactive/friday-report-prompt.md | claude -p ...` and keep the rest.
5. **Dry run, by hand.** Open a normal terminal in the project folder, run the line, and watch. It should finish and leave `workspace/work/proactive/cr-weekly-report.md`. If it stops with "permission denied", read which tool it wanted. Widen the list by one rule at a time, and only inside the proactive folder. Never switch to "allow everything".
6. **Check the output.** Compare `cr-weekly-report.md` with the 3B result: the same counts, the same keys, no Bug or Task rows, no Done items. Ask the agent to compare them and list differences. A difference is either a bug in the prompt file (fix it and re-run) or a mistake in 3B (note it).
7. **Write the run notes.** In `run-notes.md` add: the command, what each part allows, what the run is NOT allowed to do, how to check the result each week (three things you look at), and how to stop it.
8. **Optional: schedule it.** Only after a clean dry run, and only if you want it. Ask the agent to explain, in plain words, how to start the same line every Friday at 08:00: a cron entry on Mac or Linux, Task Scheduler on Windows, or simply a calendar reminder that says "run the Friday line". Write the choice into `run-notes.md`. A reminder is a fully valid answer. If you set up a real timer, note that your computer must be on and logged in at that time.

## Definition of Done

- `workspace/work/proactive/friday-report-prompt.md` exists with the rules, fixed date, input file, one output path, and a "stop and say so" rule. It contains no secret.
- `workspace/work/proactive/run-notes.md` has the one-line command, with only flags the learner saw in `--help`, and explains what is allowed and what is not.
- `workspace/work/proactive/cr-weekly-report.md` was generated by that command (not typed in the chat) and matches the 3B counts.
- The learner ran the command by hand (the dry run). Scheduling is optional.

## Hints (mentor: one at a time)

1. If the run asks for permission and stalls, ask: which tool did it ask for, and does the job really need it?
2. If the learner wants to "allow everything to make it work", ask: if this ran at 3 a.m. with nobody watching, what is the worst it could do with that permission?
3. If the report differs from 3B, ask: does the prompt file state the date and the "not Done" rule in the same words as 3B?

## What you just learned

An agent can run with no chat: a saved prompt, one command, a narrow permission list, one output folder. You also learned the order that keeps this safe: look at the flags, run it by hand, check the result, and only then let a timer do it.

**Bring it to your job:** pick one report you build every week, write its prompt file the same way, and do only the dry run this week. Add the timer next week if the output is right twice in a row.

## Mentor reference

Expected output (the sample export, report date 2026-10-24) is the same as in 3B: 16 CRs by status (Backlog 4, In progress 6, In review 2, Blocked 2, Done 2); overdue COR-102, COR-104, COR-114, COR-125; over budget COR-102, COR-106, COR-125; stale COR-107, COR-115, COR-117; needs an owner COR-112, COR-120. COR-109 (Done) and COR-124 (exactly 14 days) must not appear in the lists. No Bug or Task rows.

Check the prompt file for: one output path; "write nowhere else"; the fixed date; "stop and say so" instead of guessing; no key, password, or personal data.

Check the command: it uses `-p` (print mode), a permission list that names only the tracker data folder for reading and the proactive folder for reading and writing, and no `Bash`. The mode `dontAsk` means anything outside the list is refused, which is what you want when nobody is watching. If the learner's version of the tool names these flags differently, accept the equivalent that appears in their own `--help`. Whether a path rule such as `Edit(workspace/work/proactive/**)` is accepted in your version is worth testing in the dry run: ask the learner to try writing a file outside the folder and confirm it is refused. If the tool is not installed on the learner's machine, the command stays in `run-notes.md` as the plan, and the learner does the dry run in the chat by pasting the prompt file's content (it then proves the prompt, not the permissions).

Scheduling: a calendar reminder is acceptable. If the learner sets a cron entry or a Windows task, check it calls the same one line, writes only into the proactive folder, and runs from the project folder.

Red flags: the word `bypassPermissions` or "allow all tools" anywhere; a token or key in the prompt file; the output path pointing outside `workspace/work/`; `run-notes.md` without a stop instruction.
